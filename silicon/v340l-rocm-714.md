Date: 2026-08-28. **Own host.** Not a ROCm fork. Not a vLLM PR. hippih / extras stay HIP. No tok/s.

Companion: [v340l.md](v340l.md) (ISA + same-host ban). Path lock: extras first; hippih gfx900 TU later, on this host.

## Verdict (one page)

**Official 7.14 will not compute on V340L.** HIP may still name `gfx900`. Prebuilt rocBLAS / math libs abort (no `.dat`). TheRock nightlies advertise `device-gfx900` and have shipped a gfx900 rocBLAS payload in at least one 7.13a wheel. That nightly is not sanity-tested and has no runner. hipBLASLt / CK / rocWMMA / hipTensor are out. First iron bar is one GEMM **if** `TensileLibrary_lazy_gfx900.dat` exists — not tok/s.

## Official 7.14 — still ❌ both Vega gens

Compatibility matrix (2026-07-16): Instinct column is MI355/350/325/300/250/210/100 (`gfx950` / `gfx942` / `gfx90a` / `gfx908`). Radeon PRO has **V620**, not V340L. **MI25 / gfx900 and MI50 / gfx906 are absent.**

Linux install sysreqs table (page dated 2026-04-17; it points at the 7.14.0 matrix):

| GPU | LLVM | Support |
|---|---|---|
| Instinct MI25 | gfx900 | ❌ |
| Instinct MI50 | gfx906 | ❌ |
| Radeon PRO VII / Radeon VII | gfx906 | ❌ |

Legend on that page: **“The HIP runtime might continue to run applications for an unsupported GPU, but prebuilt ROCm libraries are not officially supported and will cause runtime errors.”**

That is QA scope, not a kernel delete. Linux 6.18 amdgpu product table still lists V340L under **VEGA10**, GC 9.0.1.

**Never install official 7.14 debs on the V340L host** and expect GEMM.

## HIP / ROCr — no hide-gfx900 filter

No hide-gfx900 filter found in HIP / ROCr this pass. pytorch#179865 names `GPU arch : gfx900` — the device was enumerated.

| File | What it does |

| `ROCm/clr` `hipamd/src/hip_comgr_helper.cpp` | Same map: `{"gfx900", "gfx9-generic"}` |

**Do not set `HSA_OVERRIDE_GFX_VERSION=9.0.6` on V340L.** That is a gfx906 lie. `sramecc-` patches are **gfx906-only**. Real Vega 10 already reports gfx900.

## Compile `--offload-arch=gfx900`

Read `ROCm/llvm-project` `amd-staging`: `GCNProcessors.td` (`f2e9e8cf`), `AMDGPU.td`.

| Target | Mix / DOT |
|---|---|
| `gfx900` (`FeatureISAVersion9_0_0`) | **`FeatureMadMixInsts`** → `v_mad_mix_*` |
| `gfx906` (`FeatureISAVersion9_0_6`) | `FeatureFmaMixInsts` + DL DOT |
| `gfx9-generic` (`FeatureISAVersion9_Generic`) | **Neither.** Drops `v_mad_mix` |

`gfx9-generic` objects may load as a HIP fallback. They are the wrong ISA. **gfx906 objects will not load.** Compile `--offload-arch=gfx900` only.

## rocBLAS — logic still in tree; official 7.14 does not ship the `.dat`

`ROCm/rocm-libraries` `develop` still lists **gfx900** and **gfx906:xnack-** through `TARGET_LIST_ROCM_7.13` (`projects/rocblas/CMakeLists.txt`).

Logic YAML still present: **87** `vega10` (gfx900), **131** `vega20` (gfx906). Example still names **Device 6864**: `projects/rocblas/library/src/blas3/Tensile/Logic/asm_lite/vega10_Cijk_Ailk_Bjlk_HB.yaml` (`d92d89ac`). `tensile_host.cpp` still has `LazyLoadingInit::gfx900`.

**Official 7.14 packages do not ship the `.dat`.** A TheRock / mixa3607-recipe gfx900 build can emit one from in-tree YAML. That is the current path — not a 6.x catalog copy.

**Fallback only** (if the gfx900 `.dat` is missing after a rebuild): copy `*gfx900*` Tensile from **6.3.4**. Not the gfx906 path. Not official 7.14 debs.

## Minimum viable stack (when cards land)

1. **Own host.** Inbox amdgpu + vega10 firmware + amdkfd. **kfd bind.** No V620. No Mac vendor blob.
2. **TheRock `device-gfx900`** **or** mixa3607 recipe with `FAMILIES=gfx900` (ROCWMMA / hipBLASLt-provider / CK-class extras OFF).
3. **`hipcc --offload-arch=gfx900`** hello. Never `gfx9-generic`. Never gfx906 fatbins.
4. **rocBLAS GEMM if `TensileLibrary_lazy_gfx900.dat` exists.** That is the compute bar.
5. **Fallback only:** copy `*gfx900*` Tensile from **6.3.4**.
6. **Never** official 7.14 debs. **Never** mixa3607 gfx906 images. **Never** the V620 box.

## First success on iron (8× V340L)

Not tok/s. In order:

1. `lspci -nn` → **16** functions, `1002:6864`. `LnkSta` Gen3 x16 per card (two dies share it). BAR0 ≈ **8G/die**, not a V620 32G.
2. `rocminfo` → **`gfx900` × 16**.
3. `hipcc --offload-arch=gfx900` hello. Load + launch.
4. ISA dump: **`v_mad_mix_*` / `v_pk_fma_f16`**. **No** `v_dot*`.
5. One rocBLAS GEMM on device 0 **if the gfx900 `.dat` is present**. `rocblas_*gemm` returns 0; `hipDeviceSynchronize` clean.

Stop there. Dual-die scheduling, 8 GB packing, and hippih come after.

## What we should add / improve

- On first boot: list `lib/rocblas/library/*gfx900*`. Record the SHA of `TensileLibrary_lazy_gfx900.dat`. If missing: TheRock / mixa3607-recipe rebuild, then 6.3.4 copy. Do not invent a new YAML first.
- hippih: gfx900 TU (`mad_mix` / `pk_fma`), wave64, 64 KB LDS. New objects. Not a retarget of extras or gfx906.
- Keep a mixa3607-shaped recipe (`FAMILIES=gfx900`). Do not publish gfx906 wheels as gfx900.
- Do **not** open PRs to upstream vLLM.
