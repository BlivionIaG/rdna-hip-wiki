# W8A8 INT8 / `sdot4` — extras vs contract

Date: 2026-09-01. Tip **`rdna2_extras` @ `83de31cf`** (read-only). FA pin stays closed. Occupancy leftover is **FA prefill `(N, 1)` / LDS 64 KiB WG**, not this format. Do not invent tok/s. Do not land this before that leftover.[^c-83de31cf][^isa]

Companions: [sdot4-explore.md](sdot4-explore.md), [int8-moe.md](../gemm-moe/int8-moe.md), [w8a8-fp8.md](w8a8-fp8.md), [w8a8-mxfp4.md](w8a8-mxfp4.md) (study), [silicon/arch-and-memory/valu.md](../../silicon/arch-and-memory/valu.md), [silicon/lds-and-tiles/lds-tiles.md](../../silicon/lds-and-tiles/lds-tiles.md) recipe 9.[^f-83de31cf-CMakeLists-txt][^f-83de31cf-ops-h]

gfx1030 has **no** WMMA / MFMA / FP8 unit. Integer inner op is `V_DOT4C_I32_I8` / `__builtin_amdgcn_sdot4`. Peak IU8 **512** ops/clk/CU vs packed FP16 **256** (GPUOpen RX 6950 XT table) — the 2× only shows when **both** sides are integer i8 **and** the kernel is compute-bound.[^isa][^gpuopen]

**Occupancy first.** LDS comes from the `DesignI8` constants and the `__shared__` arrays. VGPR counts are the PR #221 author's `llvm-readobj --notes` figures from a ROCm **10.0** build of `cda6ef6e`, not from the 7.14.0 pin; re-check them on 7.14. Waves/SIMD use the [vgpr-occupancy.md](../../silicon/occupancy/vgpr-occupancy.md) ladder (round to 16, `floor(1024 / aligned)`). WG/WGP = min(VGPR term, LDS term over 128 KiB). The last two columns are arithmetic.[^t8d-g-design][^t8d-pr221]

| Kernel (tile BM×BN×BK, TM×TN) | Block | `__launch_bounds__` / `waves_per_eu` | Static LDS | VGPR (PR, ROCm 10.0) → waves/SIMD | WG/WGP (arith.) |
|---|---|---|---|---|---|
| `gemm_w8a8_i8_kernel<D1_I8>` 128×128×64, 8×16 | 128 (4 waves) | `(P::T)` / none | 2 × (8 + 8 KiB) = 32,768 B | 229 → 240 → 4 | **4** (LDS 4, VGPR 4) |
| `<D4_I8>` 256×128×64, 8×16 | 256 (8) | `(P::T)` / none | 2 × (16 + 8 KiB) = 49,152 B | 219 → 224 → 4 | **2** (LDS 2, VGPR 2) |
| `<D6_I8>` 64×128×64, 8×8 | 128 (4) | `(P::T)` / none | 2 × (4 + 8 KiB) = 24,576 B | 139 → 144 → 7 | **5** (LDS-bound; VGPR 7) |
| `<D7_I8>` 64×64×64, 8×8 | 64 (2) | `(P::T)` / none | 2 × (4 + 4 KiB) = 16,384 B | 149 → 160 → 6 | **8** (LDS-bound; VGPR 12) |
| `w8a8_act_quant_per_token_k` | 256 | `(256)` / none | `smax[8]` = 32 B | 23 → 32 → 16 (cap) | not LDS/VGPR bound |
| `hc_silu_quant_k` | 128 | `(128)` / none | `smax[4]` = 16 B | 31 → 32 → 16 (cap) | not LDS/VGPR bound |
| `hc_up_mix_prefill_i8_k` 128 × 128 (4 HC × 32 H) × 64 | 256 (8) | `(256)` / none | `As[16][132]` + `Bs[16][130]` u32 = 16,768 B | 127 → 128 → 8 (top of the 8-wave rung) | **4** (VGPR-bound; LDS 7) |

How the VGPR term is counted: in WGP mode a WG's waves spread over the 4 SIMD32s ([vgpr-occupancy.md §4](../../silicon/occupancy/vgpr-occupancy.md)). A 4-wave WG puts 1 wave on each SIMD, an 8-wave WG puts 2, and D7's 2-wave WG gives 4 × 6 / 2 = 12. `hc_up_mix` at 127 is one VGPR under the 128 → 7-wave cliff; a compiler that adds one VGPR drops it to 3 WG/WGP (144 → 7 waves → 3 WGs of 2 waves per SIMD; arithmetic).[^t8d-pr221]

- **Builtins.** The GEMM and HC-up inner loops use only `__builtin_amdgcn_sdot4(a, b, acc, false)` (signed i8, no clamp). A and W come in through `__builtin_amdgcn_raw_buffer_load_b128` on a buffer resource with `num_records` = `M·K` / `N·K` bytes. The sigmoid uses `__builtin_amdgcn_rcpf`. There is no `sdot8`, no `fdot2` in these kernels, and no WMMA.[^t8d-g-sdot4][^t8d-g-rsrc][^t8d-g-hcup]
- **GEMM tile.** BK = 64 i8 = 64 B per LDS row. NBUF = 2 double-buffers the K tiles, with one `__syncthreads` per tile. Fragments are `ds_read_b64` (8 i8 = 2 dwords per K step). Each row's four 16-B chunks are XOR-swizzled (`kcc ^ ((r / SRP) & 3)`, SRP = 2). B dwords are rotated inside each 8-B fragment (BROT), which the source says puts the two `sdot4` operands in different VGPR banks. The 8-step K loop is `#pragma unroll 1`. Per K step, a D1/D4 thread issues TM·TN·2 = 256 `sdot4` against 8 A + 16 B b64 LDS reads (arithmetic). The swizzle is described as conflict-free in the source; not re-derived here.[^t8d-g-kernel]
- **Accumulator floor (arithmetic).** D1/D4 hold TM·TN = 128 i32 accumulators plus 48 fragment dwords per thread, before addresses and the `ra`/`rb` 16-B prefetch registers. D6/D7 hold 64 accumulators. This is consistent with the PR's 219–229 vs 139–149 split.[^t8d-g-kernel][^t8d-pr221]
- **Tail and epilogue.** A wave whose first row/column is out of range skips `compute` (`readfirstlane`-uniform `wave_live`) but still reaches every barrier. The epilogue is `acc · a_scale[row] · w_scale[col] + bias` in fp32, with scalar fp16 stores.[^t8d-g-kernel]
- **Host design pick** (`design < 0`): N ≤ 384 and M ≥ 512 → D7; else M ≤ 256 or N ≤ 384 → D6; else D1. D4 runs only when `design = 1` is passed explicitly.[^t8d-g-pick]
- **Act quant.** One 256-thread block per row. It keeps up to 2 uint4 per thread in registers for K ≤ 4096 (single pass), otherwise it re-reads x. Scale = rowmax / 127, clamp ±127, `__float2int_rn`; `a_scale` is fp32 per token. The `a_i8` / `a_scale` scratch is per device, grows on demand under a host mutex, and is shared with the HC op.[^t8d-g-quant][^t8d-g-scratch]
- **HC up + sigmoid + mix.** `As` and `Bs` are filled with scalar u32 transposed stores (`As[a_j·4 + q][a_m]`). With the wiki's 64-bank formula (`bank = dword mod 64`, [architecture.md](../../silicon/arch-and-memory/architecture.md)), SA = 132 and SB = 130 give one dword per bank for each wave32 store (arithmetic). If a wave sees only one 32-bank half (CU mode, or the WGP-mode alias the ISA leaves open), the `As` store is 2-way and `Bs` stays conflict-free. *Correction: the earlier room note "As stores 2-way bank-conflicted (SA = 132)" holds only under that 32-bank view.* Reads are b128 for `As` (4 M rows) and b64 for `Bs` (2 H columns per HC stream). Each 64-K slab takes two barriers (before and after the stage). The next slab's global loads overlap compute; there is no LDS double buffer.[^t8d-g-hcup]
- **`hc_silu_quant_k` lane use.** 128 threads, 8 halves each, single pass when R ≤ 1024. At the PR's R = 320, `nvec` = 40: wave 0 is full, wave 1 has 8 live lanes, and waves 2–3 are idle in the load and quant phases (arithmetic from `nvec = R / 8`).[^t8d-g-silu][^t8d-pr221]
- **Guards.** `TORCH_CHECK`: K % 64 == 0, and `M·K ≤ INT32_MAX` and `N·K ≤ INT32_MAX` (added in `cda6ef6e`; the buffer `num_records` and the `grow·K` offsets are 32-bit). HC op: `hc_count == 4`, R % 64 == 0, H % 32 == 0, `dai.stride(0) % 8 == 0`. The device bodies compile under `__gfx1030__ || __gfx1031__ || __gfx1032__` (widened from `__gfx1030__` in `cda6ef6e`); other device passes get empty-body stubs. The Python gate is `on_gfx10x()` plus the op being present.[^t8d-g-checks][^t8d-g-guard][^t8d-ops-w8a8]
- **Env (all default off).** `VLLM_RDNA_DENSE_W8A8_PREFILL=1` routes dense layers with ≥ `VLLM_RDNA_DENSE_W8A8_MIN_ROWS` (default 64) rows, K % 64 == 0 and an int8 shadow weight. `VLLM_RDNA_HC_W8A8_DOWN=1` runs the HC down projection through this GEMM. `VLLM_RDNA_HC_W8A8_UP=1` runs the fused up/sigmoid/mix, and only with DOWN on. The new `flashnext-w8a8-mtp2.env` recipe (#228, `ac461be8`) sets all three plus `VLLM_RDNA_DENSE_INT8=1` / `_ONLY=1`. Its header says not to promote it before quality and exactness gating. The path is lossy by design (per-token int8 activations).[^t8d-ops-w8a8][^t8d-ops-hc][^t8d-recipe]

## `sdot4` vs unpack → `fdot2`

```
W8A16 (live MoE):   load i8 W → cvt fp16 → fdot2(A16, W16)     // A stays fp16
W8A8  (spec):       quant A to i8 → sdot4(A8, W8) → i32        // both sides i8
W8A8-FP8 (live):    E4M3 → fp16 bits → fdot2                   // not integer
W4A8  (explore):    nibble → i8, then sdot4                    // not sdot8
W4A4 int (explore): both i4 → sdot8                            // after W8A8
MXFP4 / NVFP4 A4:   E2M1 unpack → fp16 → fdot2                 // sdot8 on E2M1 is wrong math
```

Unpack→`fdot2` is **not** a W8A8 implementation. It is W8A16. Using it as a “temporary sdot4” ships the wrong opcode and never sees the 512 IU8 pipe.[^gpuopen]

`sudot4` / `V_DOT4_I32_IU8` is gfx11+ (`dot8-insts`). gfx1030 has signed `sdot4` and unsigned `udot4` only — do not mix signs.[^isa][^clang-dot][^llvm-gfx1030]

## Occupancy

`__launch_bounds__` does **not** shrink LDS. Occupancy = min(VGPR, LDS, SIMD). Addressable LDS per WG is **64 KiB**; WGP pool 128 KiB; banks 64×4 B. Recipe 9 (8–16 KiB) is not the FA leftover. Do not pin this kernel `(N, 1)`. Do not treat RMSNorm HIP AOT as a reason to open this card.[^isa]

## Does this change extras / tickets?

**No.** Spec stays spec. No GEMM to retip. FA pin closed. No ticket.[^f-83de31cf-CMakeLists-txt][^f-83de31cf-ops-h]
